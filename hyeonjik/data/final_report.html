PopQA 최종 채점 보고서: Qwen2.5-7B와 Dream-v0-Base-7B

대상: 이 프로젝트의 공동 연구자. 두 모델의 정답/오답 수, 오답 유형, 0/5~5/5 분포와 채점·분류 방법 전체.

1. 데이터

PopQA 사실 11,045개에 대해 질문을 5가지 표현으로 바꿔 모델에 물었다. 한 모델당 11,045 × 5 = 55,225개 답변이다. Dream은 32 step, topk_margin 디코딩으로 생성했다. 두 모델 모두 같은 규칙으로 채점하고 같은 정책으로 오답을 분류했다.

4. 정답/오답 채점 방법

이분법이다. 모든 답변은 정답 또는 오답 둘 중 하나이고, 애매한 행을 따로 빼지 않는다. 구현은 grounded_dream/paper_grade.py이고 두 모델에 똑같이 적용한다.

  1. 답변 정리. 모델 출력에서 첫 줄/첫 문장만 쓴다. 뒤에 붙은 웹 잔해("Take the 2-minute tour" 등)와 "The film was directed by …" 같은 틀을 걷어 내고, 핵심 개체 구절만 남긴다. 정리 전 문자열과 정리 후 문자열 둘 다 후보로 쓴다.
  2. 정규화. 소문자화, 구두점·관사 제거, 공백 정리.
  3. 비교 대상. 골드 값과 골드의 모든 별칭(Wikidata alias).
  4. 로마 숫자 검사. 군주·속편 등에 붙는 I~XII는 답변과 골드가 같아야 한다. 다르면 문자열이 비슷해도 오답이다 (예: Henry II와 Henry III).
  5. 유사도. 정규화한 두 문자열이 같거나, difflib 비율 또는 토큰 정렬 비율 중 큰 값이 90 이상이면 정답.
  6. 후보 중 하나라도 조건을 만족하면 정답, 아니면 오답.
TH = 90
def is_correct(r):
    cands = [norm(a), norm(core(a))]           # 정리 전/후
    golds = [norm(gold)] + [norm(x) for x in aliases]
    for c in cands:
        for g in golds:
            if roman(c) != roman(g): continue  # I~XII 불일치면 건너뜀
            if c == g or max(ratio(c, g), token_sort_ratio(c, g)) >= 90:
                return True
    return False

Ferrando et al. 2025 (arXiv 2411.14257)와의 관계

  • 논문은 thefuzz의 token_set_ratio > 90을 쓰고, 사실을 "알고 있음"(속성 2개 이상 정답)과 "모름"(전부 오답)으로 나누고 중간은 버린다. 우리는 이분법을 쓰고 아무것도 버리지 않는다. 그 점에서 논문과 같은 방향이다.
  • token_set_ratio는 한쪽 토큰이 다른 쪽에 포함되기만 해도 100이 나온다. 그래서 짧은 골드가 긴 오답 안에 들어 있으면 정답이 된다. 우리는 이 함수를 쓰지 않고 위의 더 엄격한 두 비율을 쓴다.
알려진 한계
  • 철자가 많이 달라진 같은 개체 표기(음역, 약칭 등)와, 골드의 상·하위 개념("Catholic"과 "Catholic Church")은 유사도가 90 미만이라 오답으로 판정된다.
  • 골드 자체에 문제가 있는 사실(gold_issue 2,932행)도 제외하지 않았다. 두 모델 모두 같은 행에 표시만 되어 있다.

5. 오답 유형 분류 방법

정답이 아닌 모든 행에 유형을 붙인다. 최종 유형(type3)은 entity, broken, abstain 세 가지이고, 세부 라벨 final_label(1, 2, 3, 4, 5, 6, abstain)에서 정해진다. 판단 기준은 analysis/graded/7. final/classification_policy.md와 에이전트 프롬프트 agent_prompt_en.md에 있다. 아래 단계를 순서대로 적용하고, 앞 단계에서 확신 있게 정해진 행은 뒤 단계로 넘기지 않는다.

5.1 유형 정의

  • entity: 골드가 아닌 다른 실재 개체를 답한 경우다. 세부 라벨은 세 가지다.
    • 1 관련 개체: 골드와 같은 범주이고 연결이 있다. 같은 나라·도시 안의 다른 장소, 같은 장르/직업군, 같은 작품에 참여한 다른 사람이 해당한다. 사람 이름 관계(director, producer, screenwriter, composer, author)는 질문 속 작품과 실제로 연결된 사람이면 1이다.
    • 2 무관한 개체: 실재 개체이지만 골드와 연결이 없다. 처음 보는 이름이라 확인이 안 되면 2로 두고 unverified를 켠다.
    • 4 맞은 뒤 틀림: 정답 개체를 말한 뒤 틀린 내용을 이어 붙인다.
  • broken: 생성이 망가진 답이다. 세부 라벨은 세 가지이고, 3, 5, 6 순서로 배정한다.
    • 3 질문 베낌: 답의 내용어(관사·호칭 제외)가 전부 질문에 있는 단어이거나, 질문에 나온 단어나 개체(주로 주어)를 그대로 되풀이한다.
    • 5 지어낸 이름: 서로 다른 개체의 이름 조각을 섞어 존재하지 않는 개체를 만든다. 질문에 없는 새 단어가 하나라도 있는 경우에만 5다. 예: "Producer Brandish"(질문 단어만)는 3, "John Hampton"(질문은 "father of Hampton")은 5.
    • 6 붕괴: 같은 구절의 반복, 의미 없는 열거, 문장이 깨진 출력. 반복 판정은 두 단어(bigram)가 3번 이상, 또는 불용어가 아닌 토큰이 4번 이상 나오는 경우다.
  • abstain: "모른다", "정보 없음" 같은 거절이다. 환각이 아니므로 따로 센다.

5.2 단계

  1. 문자열 규칙. 거절 정규식, 붕괴(반복) 규칙, 질문 단어 포함 여부(베낌)를 먼저 적용한다. (label_source: string-rule)
  2. Wikidata 규칙. 골드와 답변 이름을 Wikidata 개체로 찾아 SPARQL로 관계를 본다 (@en/@mul 라벨, 캐시 wd_cache.json). 나라·지역·직업·작품 참여 같은 속성 연결이 있으면 1, 후보는 있는데 연결이 없으면 2. 큰 나라는 같은 나라 안이면 1이다. (wikidata-rule)
  3. 그룹 규칙. 관계별로 정의한 범주 그룹(예: 장르군, 언어군)으로 판정한다. (group-rule)
  4. 에이전트 판정. 위 단계에서 확신이 없는 행은 정책 문서를 읽은 에이전트가 판정한다. Wikidata 결과를 힌트 열로 함께 주기도 한다. (agent+hint, agent+wikidata-hint)
  5. 교정 단계.
    • 지어낸 이름(5)은 질문 문장을 주고 다시 확인한다.
    • 처음 보는 이름 → 2 + unverified.
    • 이름 변형(E.M. Forster → E. M. Forster, 중간 이니셜 제거, 중복 단어 제거)으로 Wikidata를 다시 조회한다. (wikidata-rule-altname)
    • 동명이인이 많은 흔한 이름(같은 이름의 인물이 4명 이상이고 가장 유명한 사람의 sitelinks가 2위의 2.5배 미만)은 1에서 2 + unverified로 내린다.
    • 애매한 행은 여러 번 독립 판정해 다수결로 정한다. (vote3, unify-vote)
