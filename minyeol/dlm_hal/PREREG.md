# 후속 실험 사전 등록 (2026-11-16, 결과를 보기 전)

대상: Dream-v0-Base-7B, PopQA 1/5~4/5 사실.  개입 위치와 생성 설정은 `analysis/6_steering/README.md` 와 같다 (층 20 출력, 프롬프트 끝 토큰, 32 forward 모두, 캔버스 32, 32 step, topk_margin, 온도 0).
방향 B 는 `caa_directions.py` 와 같은 식으로 다시 만든다 (주어 5겹, 평가 행의 겹 제외, 같은 사실 안 정답 - 붕괴 평균, 길이 1).  크기 c x 54.
모든 비교는 같은 실행, 같은 배치 구성의 '개입 없음' 과 한다.  오답 유형은 정답 / entity / 붕괴(= broken) / abstain.  CI 는 행 bootstrap 10,000 (조건 간 비교는 짝지은 bootstrap).
SAE 는 쓰지 않는다.  LLaDA 는 이번에 하지 않는다.

## E1. k별 고침 비율 (기존 결과, 서술용)
`results_caa_all.jsonl` 에서 k (1~4) 별로 오답 행의 고침 비율과 정답 행의 망침 비율을 c = 0.5, 1 에서 낸다.  판정 없음.

## E2. 빼기: B 가 정답에 필요한가 (`e2_minus.py`)
대상: 1/5~4/5 정답 행 600개 (seed 7 무작위).
조건: 개입 없음 | -B c 0.5, 1, 2 | B 성분 지우기 h <- h - (h.B)B (32 forward) | +B c 1, 2 | 무작위 가우시안 단위 방향 G0~G3 c 1 | 의미 없는 방향 D0~D3 c 1 (붕괴 행을 반반 나눈 평균 차이, `caa_directions.py` 와 같음).
지표: 정답 유지율, 정답에서 벗어난 행 중 붕괴 / entity 비율.  저장된 상태로 h.B 분포도 보고한다.
- H2.1 (손상이 특별함): -B c1 의 정답 하락 - 대조 8개 (G, D) 평균 하락 >= 10 점, 짝 CI 하한 > 0, 그리고 대조 8개의 최대 하락보다 큼.
- H2.2 (유형이 방향을 따름): -B c1 에서 벗어난 행 중 붕괴 비율 >= 50% 이고 대조 8개를 합친 붕괴 비율의 2 배 이상.  +B c2 에서 벗어난 행 중 붕괴 비율 <= 20%.
- H2.3 (성분 지우기): 정답 하락 < 5 점이면 'B 성분 자체는 정답에 필요하지 않고, 반대쪽으로 밀 때만 붕괴가 생김' 으로 쓴다.  >= 5 점이고 대조 평균보다 크면 '필요' 로 쓴다.
판정 (위 행 우선):
| 조건 | 결론 |
|---|---|
| H2.1, H2.2 참 | B 축의 한쪽 끝은 붕괴, 반대쪽 끝은 과잉 확약 (entity).  인과 그림 채택 |
| H2.1 참, H2.2 거짓 | B 는 손상 크기에서 특별하지만 유형을 정하지 않음 |
| H2.1 거짓 | 빼는 쪽에서 B 가 특별하지 않음.  '흔들면 바뀐다' 를 배제 못 함 |

## E3. few-shot 기준선 (`e3_fewshot.py`)
대상: `caa_directions.py` 와 같은 행 (붕괴 310, entity 300, 정답 300, seed 5).
조건: 원래 프롬프트 (zero-shot) | 3-shot (5/5 사실에서 관계가 다른 예 3개, 주어가 대상 행과 겹치지 않음).
지표: 붕괴 -> 정답, entity -> 정답, 정답 유지.  비교 대상은 `caa_directions` 의 B c1 (25.2 / 27.0 / 69.7, 다른 실행이라 직접 차이는 서술만).
판정: few-shot 의 붕괴 -> 정답이 25% 이상이고 정답 유지가 69.7% 이상이면 'B 조향은 실용 처방으로는 few-shot 보다 못함, 논문은 메커니즘 주장으로 쓴다' 로 적는다.  아니면 'B 가 few-shot 이 못 하는 것을 한다' 로 적는다.

## E4. 두 단계 분해 (`e4_decomp.py`)
대상: 붕괴 행 중 주어 위치를 찾았고 같은 사실의 정답 문구 (주어 위치 있음) 가 있는 행 (300 예상).
공여 상태: 같은 사실의 정답 문구를 step 0 입력 (프롬프트 + 마스크 32) 으로 한 번 통과시켜 모든 층 출력을 저장.  저장된 층 20 프롬프트 끝 상태와 cosine >= 0.99 인지 확인한다 (아니면 멈춤).
주어 위치 정렬: 주어 문자열 (또는 별칭) 의 토큰 구간, 끝에서부터 맞춤.  구간 길이가 다른 행 비율을 보고한다.
조건 (모두 32 forward):
- base
- END: 프롬프트 끝, 층 20 출력을 공여 것으로 교체 (기존 19.7% 재현 확인)
- SUBJ: 주어 구간, 층 0~8 출력을 공여 것으로 교체
- SUBJ_wrong: 같은 사실의 다른 오답 문구를 공여로 한 SUBJ (있는 행만)
- SUBJ+END
- B c1, D0 c1 (같은 실행, 행 단위 겹침 비교용)
- sweep: 주어 구간 층 0~3, 4~8, 9~14, 15~20 | 프롬프트 끝 층 4, 8, 12, 16, 24 (각각 그 층 출력 하나만 교체)
가설:
- H4.1 (접근 실패가 있음): SUBJ 의 정답 >= 10% 이고 같은 행에서 SUBJ_wrong 보다 5 점 이상 높음 (짝 CI 하한 > 0).
- H4.2 (B 는 답 상태만 고침): B c1 로 고쳐진 행 중 END 로도 고쳐진 비율이 END 전체 고침률의 2 배 이상이고, 같은 계산을 D0 c1 로 한 값보다 큼.  SUBJ 로만 고쳐지고 END 로는 안 고쳐지는 행에서 B c1 의 고침률이 전체 B c1 고침률의 절반 이하.
분해 (서술): SUBJ 만 / END 만 / 둘 다 / SUBJ+END 만 / 안 고쳐짐 비율.
판정:
| 조건 | 결론 |
|---|---|
| H4.1, H4.2 참 | 아는 사실 실패 = 접근 실패 + 답 상태 실패.  B 의 한계는 접근 실패 몫으로 설명됨 |
| H4.1 참, H4.2 거짓 | 두 단계는 있으나 B 의 한계를 이것으로 설명하지 못함 |
| H4.1 거짓 | 주어 위치 초기 층 교체로는 고쳐지지 않음.  접근 실패 몫을 주장하지 않음 |

## E5. Qwen 과 방향 비교 (`e5_qwen.py`, CPU)
Qwen2.5-7B 층 20 프롬프트 끝 상태 (`data/1_raw/qwen_hidden`, 단일 forward) 로 Qwen 자신의 라벨에서 같은 사실 안 (정답 - 붕괴), (정답 - 오답) 평균 차이를 만든다.
지표: Dream B 와 cosine (사실 bootstrap CI), Qwen 방향의 반반 나눔 안정성, 무작위 방향 cosine 기준 (약 ±0.02), Qwen 상태를 Dream B 에 투영했을 때 같은 사실 안 정답 대 오답 AUROC.
판정: cosine CI 하한 >= 0.3 이고 Qwen 반반 안정성보다 크게 낮지 않으면 '부모 모델에서 이어진 방향' 으로 쓴다.  CI 상한 < 0.1 이면 'Dream 에서 새로 생긴 방향'.  그 사이는 '부분 공유'.
