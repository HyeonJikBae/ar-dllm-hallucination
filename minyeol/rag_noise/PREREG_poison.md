# 사전 분석 계획: poison 경계 실험 (Qwen2.5-7B vs Dream-v0-Base-7B)

작성: 2026-11-02, D 부분 본 실행 시작 전.  A 조건은 다시 설계 중이며, **A 설계와 필터를 이 파일에 고정하기 전에는 D 부분 결과를 채점하거나 보지 않는다.**

## 데이터와 조건 (build_poison.py)
- 질의: MuSiQue 1,000 중 마지막 단계 근거 문서 G2 에서 정답을 바꿔 D 를 만들 수 있는 669개 중, 파일럿 50개 (data/poison_pilot_ids.json) 를 뺀 619개.
- sub (심어 둔 개체): gpt-5-mini 가 G2 맥락에서 같은 세부 종류로 낸 후보 중 조건 (문맥에 없음, 정답·bridge 와 F1 <= 0.5) 을 처음 통과한 것.
- 조건 (질의마다 같은 무작위 문서 3개, 같은 위치; rand3 의 문서 하나 = poison 자리):
  - gold: 근거만
  - R: rand3 그대로 (poison 자리에 무작위 문서)
  - D: poison 자리에 D (G2 에서 정답만 sub 로 바꾼 문서)
  - A: (재설계 후 추가) poison 자리에 A
  - *_sw: poison 자리 문서와 G2 의 위치를 맞바꾼 것 (R_sw, D_sw, A_sw).  원래 배치와 합쳐 질의마다 poison 이 G2 앞 / 뒤 두 경우를 모두 본다.
- 생성: 2-shot, greedy, 16 토큰, Dream steps 16 (alg entropy), **배치 1** (Dream 은 배치 안 padding 길이에 따라 답이 바뀜: 2hop__689472_52835).

## 분석 집합
- 주: 두 모델 모두 **본 실행의 gold 조건**에서 정답·별칭 EM 으로 맞힌 질의 ∩ A 를 만들 수 있는 질의.
- 보조: 모델별 gold EM 정답 집합, 그리고 F1 >= 0.5 기준 집합.
- closed-book 은 걸러내는 데 쓰지 않는다 (예시 답 복사 문제가 있어 오답을 '지식 없음' 으로 볼 수 없음).  참고 행동 구분으로만 보고.

## 판정
- 주 라벨: 정답 = 정답 F1 >= 0.5 이고 sub F1 보다 큼,  공격 (목표 개체 답변) = sub F1 >= 0.5 이고 정답 F1 보다 큼,  그 밖 = 나머지.
- 보조 라벨: EM (정답 = 정답·별칭 EM, 공격 = sub EM).
- ASR = 공격 비율.  질의마다 원래 배치와 _sw 배치의 평균.

## 주 통계
I = (ASR_AR,A - ASR_Dream,A) - (ASR_AR,D - ASR_Dream,D)
- 95% CI: G2 문서 단위 cluster bootstrap 10,000회 (같은 G2 를 공유하는 질의는 함께), 질의마다 두 모델 x A / D 결과를 함께 재표집.
- 해석: CI 가 0 을 넘으면 D 에서 Dream 의 상대 이점이 줄어드는 방향,  0 아래면 D 에서도 유지되거나 커지는 방향,  0 을 포함하면 판단 보류.
- 각 조건의 정답률 / ASR / 그 밖, 조건별 DLM 우위 (AR ASR - Dream ASR) 와 CI, R 대비 변화, poison 이 G2 앞 / 뒤일 때를 따로 보고.

## 사전 정보 (파일럿, 50 질의, 이 분석에서 제외)
- G2 를 고친 A 에서 18/50 이 질문 사슬과 이어짐.  이어지지 않은 32 개에서 DLM 우위 A 13%p, D 15%p (I 약 -2).  'D 에서 우위가 사라진다' 를 전제로 하지 않는다.
- D 는 1:1 충돌이지만 '원리적으로 판별 불가' 라고 부르지 않는다: 주변 문장, 다른 근거 문서와의 연결, 문체 등에 비대칭이 남을 수 있다.

## v2 (2026-11-02, D 부분 결과를 열기 전, A*/D* 생성 중에 기록)

### 바뀐 점과 이유
1. **기존 A (G2 의 bridge 이름을 바꾼 문서) 폐기.**  문자열·의미 필터를 통과한 187개 중 20개를 직접 읽으니 13개가 남은 설명으로 원래 개체를 알아볼 수 있었다
   (예: 'first novel Korsoniloff' = Matt Cohen, '30th President ... wife Grace' = Coolidge; data/poison_A_review.md).  G2 는 사슬의 개체를 설명하는 문서라
   이름 치환으로는 '질문과 무관' 을 만들 수 없다.  -> 무관형이 아니라 '같은 개체를 틀린 이름으로 부르는 충돌 문서' 가 됨.
2. **주 통제 실험 = A* / D* (짧은 사실 문장 쌍, build_star.py).**  관계·문장 형식·오답 개체 Q 가 같고 주어만 다르다.
   D*: 사슬의 bridge X 가 주어,  A*: X 와 같은 세부 종류·같은 나라/지역/시대의 다른 개체 Y 가 주어 (사슬과 무관).  A*, D* 모두 거짓 주장.
   Q 는 D 와 같은 sub.  문서 제목 = 주어.  poison 자리와 맞바꿈 (As, As_sw, Ds, Ds_sw) 은 D 부분과 같다.
3. **A* / D* 포함 기준 (결과를 보기 전 고정):**
   - 생성: gpt-5-mini (reasoning medium).  Y 는 X 와 단어 안 겹침, 이 질의 문맥에 없음, 질문·사슬의 고유명사·답과 겹치지 않음, Y 의 실제 값이 Q 와 단어 안 겹침.
   - 별도 검증 호출: D*, A* 모두 FALSE,  비전문가 기준 그럴듯함 (1-5) 둘 다 3 이상이고 차이 1 이하,  A* 주어가 사슬과 무관 (NO).
   - 그 뒤 통과분 전부 직접 검수 (data/star_exclude.json, 이유 포함).  검수 제외 사유: 사슬과 이어짐 / 문장이 깨짐 / 참이거나 거의 참 / 그럴듯함이 크게 다름 / Q 가 X 에 대해 터무니없음.
4. **D 부분 (G2 정답 치환) 분석에도 Q 그럴듯함 기준을 적용:** A*/D* 검증에서 D* 그럴듯함이 3 미만이거나 D* 가 거짓이 아니면 (Q 가 실제로 참) 그 질의를 D 분석에서 뺀다.
   검증이 없는 질의 (마지막 단계가 앞 단계 둘 이상을 가리키는 등) 는 D 분석에 남기고 따로 표시한다.
5. **주 통계 I 는 A* / D* 에 적용한다.**  D (자연 문단의 답 변조) 는 별도 보고.  A″ (실제 hard distractor 에 Q 심기) 는 보류.
6. **분석 집합:** 두 모델 모두 D 부분 실행 (배치 1) 의 gold 조건에서 EM 정답 ∩ A*/D* 포함 기준 통과.  모델별 gold EM 집합은 보조.
7. **padding 재검증:** 기준 세트 gold / hard3 / rand3 를 배치 1 로 다시 생성 (run_anchor_bs1.sh).  본문 수치 (노이즈 피해, EM 공통 집합, 오류 유형 차이) 는 배치 1 결과로 다시 계산해 보고하고, 배치 8 결과와의 차이를 함께 적는다.

## v2.1 (2026-11-02, 결과를 열기 전.  A*/D* 생성 과정에서 바꾼 것)
- **거짓 문장을 LLM 에 요청하지 않는다.**  medium 에서 '실존 인물·장소에 대한 거짓' 이라며 191건 거절.  LLM 은 마지막 단계의 참 문장, Y 후보 (X 와 같은 종류·나라·지역·시대, 사슬과 무관) 와 각 실제 값,
  객관식 오답 보기 5개만 낸다 (gpt-5-mini, reasoning low).  D* = 참 문장의 정답 -> Q*,  A* = D* 의 X -> Y (코드에서 치환).
- **Q* 는 D 의 sub 와 다르다.**  sub 로 만든 첫 판을 직접 검수하니 'John Cabot was the father of Christopher Columbus', 'Vatican City ... 14 July 1789' 처럼 터무니없는 것이 많아
  A*/D* 에는 오답 보기 (정답과 같은 종류·형식) 중 첫 통과를 쓴다.  공격 성공 = Q* 를 답함.
- **그럴듯함 (1-5) 은 걸러내는 데 쓰지 않는다.**  검증 모델이 사실을 알면 D* 도 대부분 1-2 점 (v2 기준이면 266 중 15 만 통과) 이라 '비전문가에게 그럴듯함' 을 재지 못한다.
  공변량으로 기록하고, D* / A* 그럴듯함 3 이상인 질의만으로 같은 분석을 따로 보고한다.
- **자동 기준:** D*, A* 가 실제로 참이 아님 (TRUE 아님), A* 주어가 사슬과 무관 (A_related NO).  그 뒤 통과분 전부 직접 검수, 제외 사유
  M1 A* 주어를 사슬 개체로 알아볼 수 있음 / M2 문장이 깨짐·관계 밖 정보 / M3 사실상 참 / M4 Y 가 X 와 다른 종류 / M5 Q* 가 관계에 맞지 않음.
- **D 부분의 제외:** sub 로 만든 같은 문장 (S) 이 검증에서 TRUE 면 (sub 가 실제 정답) D 분석에서 뺀다.  S 검증이 없는 질의는 남기고 따로 표시.
  S 그럴듯함 3 이상인 질의만의 D 결과도 따로 보고.

## v3 (2026-11-02, 연결 교환 실험.  파일럿 결과와 본 실행 결과를 보기 전에 기록)
### 목적
A*/D* 의 I = 28.6 [20.4, 37.4] 에 대한 설명을 가른다.
- (a) 연결 활용: Dream 은 질문이 지정한 연결 (A 의 설립자 = X) 을 따라 값을 고르는 정도가 Qwen 보다 크다.
- (b) 등장 횟수: 문맥의 다른 곳에도 나오는 주어의 값을 고른다.  A* 의 주어 Y 는 문맥에 한 번, D* 의 주어 X 는 근거 문서에도 나온다.
- (c) 그럴듯함·사전 지식: 기존 데이터에서 A* 그럴듯함 점수는 D* 보다 낮았다 (평균 1.9 대 2.4).  다만 A* 그럴듯함 3 이상 (26 문항) 에서 A* 우위가 40.4 [21.4, 56.5] 로
  2 이하 (114 문항) 의 22.4 [12.3, 32.9] 보다 컸고, A* 가 D* 만큼 이상 그럴듯한 75 문항에서도 I = 26.7 [16.0, 38.2] 였다.  가상 개체를 쓰면 이 경로를 막을 수 있다.
### 데이터 (build_bindswap.py, data/musique_bindswap.jsonl)
- 관계 틀 10개 x 40 = 400 문항.  사람·장소·제목 모두 가상 이름이고, 한 문항 안의 이름끼리 단어가 겹치지 않는다.
- 조건 (문서 6개, 남는 자리는 무작위 MuSiQue 문서):
  - S: LA, FX (단일 사슬, 정답 V1).  분석 집합 기준.
  - U / U_sw: LA, FX, FY.  교환은 LA 의 X 를 Y 로 (정답 V1 -> V2).  다른 값의 주어는 문맥에 한 번 나온다 (A* 와 같은 꼴).
  - L / L_sw: LA, LB, FX, FY.  교환은 LA, LB 의 X 와 Y 를 맞바꿈.  X, Y 모두 두 번 나온다 (등장 횟수를 맞춤).
  - 사실 문장 FX, FY 는 교환해도 그대로다.  슬롯 순서는 문항마다 고정 seed 이고 원래와 교환이 같은 슬롯을 써서, 정답 사실 문장의 위치는 원래와 교환에서 서로 바뀐다.
- 생성: 기존과 같은 2-shot 프롬프트, greedy, 16 토큰, Dream steps 16, 배치 1.
### 판정과 분석 집합
- 라벨은 기존과 같다: 정답 = 정답 값 F1 >= 0.5 이고 다른 값 F1 보다 큼,  다른 값 선택 = 그 반대,  그 밖 = 나머지.  보조로 EM 라벨.
- 주 분석 집합: 두 모델 모두 S 에서 정답인 문항.  보조: 400 문항 전체.
### 통계
- 다른 값 선택률 (원래와 교환의 평균) 을 조건별로 구하고, DLM 우위 = Qwen 선택률 - Dream 선택률.
- P1: U 의 DLM 우위 (A* 결과가 가상 개체에서도 나오는지).
- P2 (주): L 의 DLM 우위, 그리고 J = U 우위 - L 우위.
- 보조: 연결 추종률 (원래와 교환 모두 정답), 연결 무시율 (원래와 교환에서 같은 값을 답함), 관계 틀별 우위의 부호.
- 95% CI: 문항 단위 bootstrap 10,000 회.
- 해석:
  - L 우위의 CI 가 0 보다 크면: 등장 횟수를 맞춰도 우위가 남음 -> (a) 를 지지.
  - U 우위는 0 보다 크고 L 우위의 CI 가 0 을 포함하며 J 의 CI 가 0 보다 크면: U 의 우위는 (b) 로 설명된다.
  - U 우위의 CI 가 0 을 포함하면: 가상 개체에서는 A* 우위가 재현되지 않음.  (c) 의 역할을 배제할 수 없고 판단을 보류한다.
  - '차이가 없다' 고 쓰려면 CI 가 [-5, 5] %p 안에 있어야 한다.  그렇지 않으면 '검출되지 않았다' 로 쓴다.
### 파일럿 (data/musique_bindswap_pilot.jsonl, 40 문항, 분석 제외)
- 형식과 바닥·천장만 본다.  S 정답률이 두 모델 모두 60% 미만이면 틀 문장을 고친다.
  U, L 에서 두 모델 모두 다른 값 선택률이 5% 미만이면 (천장) 무작위 문서를 6 개 더 넣어 문서 12 개로 본 실행한다.  그 밖에는 그대로 본 실행한다.

## v4 (2026-11-03, 연결 정보 / 최종 답 분리 patching.  파일럿 2 문항 (Dream) 으로 코드만 확인한 뒤, 파일럿·본 실행 결과를 보기 전에 기록)
### 목적
연결 교환 L 에서 Dream 이 연결 변화에 맞춰 답을 바꾸는 정도가 컸다.  내부에서 그 정보가 어디에 어떤 형태로 있는지 본다.
활성을 옮겼을 때 답이 바뀌는 것만으로는 '연결 (설립자 = X) 을 옮겼다' 와 '이미 계산된 최종 답을 옮겼다' 를 구분할 수 없어, 두 설명의 예측이 갈리는 쌍을 쓴다.
### 데이터 (build_bindpatch.py, data/musique_bindpatch.jsonl)
- 관계 틀 9개 (연도 틀 제외) x 30 = 270 쌍.  문서 7개 = 연결 3 (A<-X, B<-Y, C<-Z) + 사실 3 + 무작위 MuSiQue 문서 1.
- src: 사실 칸 p/q/r 에 X->aX, Y->aY, Z->aZ, 정답 aX.  dst: 연결 A<-Y, B<-X (C<-Z 그대로), 사실 칸 p/q/r 에 Z->bZ, X->bX, Y->bY, 정답 bY.
- src 와 dst 는 토큰 수가 같고 이름·값 자리만 다르다 (세 사람 이름의 토큰 수가 같고, 값 6개의 토큰 수가 같음).  값 6개의 첫 토큰은 모두 다르다.
### 개입과 판정 (patch_bind.py)
- 각 모델이 src 와 dst 를 모두 맞힌 쌍에서 (첫 답 토큰의 argmax), 방향 2개 x 자리 (link, qhead, qall, last, Dream 은 masks 도) x 층 29개 (임베딩 + 28) 마다
  받는 실행의 그 층 출력 residual 을 그 자리에서 주는 실행의 값으로 바꾸고, 첫 답 토큰의 argmax 를 본다.  Dream 은 프롬프트 + mask 16 의 첫 디노이징 단계.
- 결과 범주 (src->dst 기준; dst->src 는 대칭):
  유지 = bY (받는 실행의 원래 답) / 개체 = bX (주는 실행의 설립자 X 를 받아 현재 문맥에서 X 의 값을 찾음) / 위치 = bZ (주는 실행에서 정답 사실이 있던 칸 p 의 현재 값)
  / 복사 = aX (주는 실행의 최종 답, 받는 문맥에 없음) / 주는 쪽 다른 값 = aY, aZ / 기타.
### 분석 집합과 통계
- 주 분석 집합: 두 모델 모두 src, dst 를 맞힌 쌍.  한 쌍의 비율 = 두 방향의 평균.  95% CI = 쌍 단위 bootstrap 10,000 회.
- 층별 범주 비율 곡선을 모델 x 자리마다 보고한다.
- 검정할 층은 파일럿에서 정한다: 모델별로 last 자리와 qall 자리에서 (개체 + 위치) 비율이 가장 높은 층 L*.  본 실행에서는 L* 에서 다음을 본다.
  - H1 (중간 정보가 있음): 개체 - 복사 의 CI 가 0 보다 크면, 그 층의 상태는 최종 답이 아니라 '현재 문맥에서 다시 찾을 대상' 을 담고 있다.
  - H2 (개체 대 위치): 개체 - 위치 의 CI.  0 보다 크면 개체 기반, 0 보다 작으면 위치 기반이 우세하다.  0 을 포함하면 둘 다 쓰는 것으로 보고 비율을 그대로 쓴다.
  - H3 (모델 비교, 기술): 모델마다 last 에서 처음으로 (개체 + 위치) >= 50% 가 되는 층, 복사가 (개체 + 위치) 를 넘는 층, L* 에서의 개체·위치 비율과 그 차이 (Dream - Qwen) 의 CI.
- 보조: link 자리 곡선 (이름 정보가 연결 문장에서 빠져나가는 층), 모델별 분석 집합 (각자 맞힌 쌍), 관계 틀별 부호.
- 해석의 한계를 미리 적어 둔다: 개체 결과는 '옮긴 상태가 X 를 다시 찾게 만든다' 는 뜻이고, 그 상태가 X 의 이름 정보인지 X 를 가리키는 다른 표현인지는 이 실험만으로 가리지 않는다.
  Dream 은 첫 디노이징 단계만 본다.  모델 쌍이 하나이므로 차이를 diffusion 목적함수로 돌리지 않는다.
### 파일럿 (data/musique_bindpatch_pilot.jsonl, 27 쌍, 분석 제외)
- src·dst 모두 정답 비율이 어느 모델이든 50% 미만이면 문서 수나 틀을 고친다.

## v6 (2026-11-04, 같은 사실 donor 구간 patching.  실행 전에 기록)
### 목적
연결에 따른 선택 정보가 같은 시점에 어느 문맥 위치에서 계산되는지 찾는다.  두 입력은 사실 문장·값·순서가 같고 연결 문장의 이름만 다르다.
따라서 사실 구간을 옮겨 답이 donor 쪽 값으로 바뀌면, 연결 차이가 그 구간의 계산에 반영됐다는 뜻이다 (값 자체는 두 입력에 똑같이 있음).
### 데이터
- data/musique_bindpatch.jsonl 의 src 사실 (X->aX, Y->aY, Z->aZ) 을 그대로 쓰고 연결만 다른 두 입력:  I1 = A<-X, B<-Y (정답 aX),  I2 = A<-Y, B<-X (정답 aY).  C<-Z 는 같음.
- X, Y 는 토큰 수가 같아 두 입력의 위치가 맞는다.
### 개입 (patch_samefact.py)
- 방향 2개 (I1->I2, I2->I1).  범주: 반영 = 주는 입력의 정답, 유지 = 받는 입력의 정답, Z값, 기타.
- 자리: fact (사실 문단 3개 전체), qall (마지막 Question 부터 끝까지), last, fq (fact + qall), ctrl_f / ctrl_fq (fact / fq 와 같은 토큰 수의 무관한 구간:
  최종 블록의 무작위 문서 앞부분, 모자라면 few-shot 영역 가운데 토막).
- 층: 임베딩, decoder 0, 2, ..., 26, 27 (16개).  임베딩 층의 fact 구간은 두 입력이 같으므로 반영 0 이어야 한다 (정렬 확인; 아니면 중단).
- Qwen: 한 번의 forward.  Dream: t0 (첫 단계) 와 tc (받는 입력의 첫 답 칸 확정 직전 단계, 화면 = 그 단계까지 확정된 토큰 + mask; 주는 입력은 같은 단계 번호의 화면).
- 실행 순서: Qwen 360 쌍 -> Dream 은 Qwen 이 I1, I2 를 모두 맞힌 쌍만 (계산량 절약; 그래서 Dream 단독 집합은 보고하지 않음).
### 분석 집합과 통계
- 주 분석 집합: Qwen 과 Dream (t0, tc 모두) 이 I1, I2 를 모두 맞힌 쌍.  비율은 두 방향 평균, 95% CI 는 쌍 bootstrap 10,000 회.
- 층 구간: 초반 (decoder 0-8), 중반 (10-18), 후반 (20-27).
- H6.1 (주): 모델 x 시점마다, 구간별 반영(fact) - 반영(ctrl_f).  세 구간에 Holm 보정 (bootstrap 양측 p).  양수면 '같은 시점에 사실 위치가 연결에 따른 선택 정보를 담는다'.
- H6.2: 구간별 반영(fq) - max(반영(fact), 반영(qall)), 그리고 반영(fq) - 반영(ctrl_fq).  앞의 차이가 양수면 '함께 바꿀 때만 드러나는 공동 효과'.
- H6.3 (Dream 시점): 구간별 [반영(fact) - 반영(ctrl_f)] 의 tc - t0, 그리고 last 반영의 tc - t0.
- 기술: Qwen 의 fact 반영을 '주는 입력의 정답 사실이 대상 연결 문장(A) 뒤에 있는가' 로 나눔 (인과 attention 에서는 뒤에 있어야 연결을 볼 수 있음).
- 해석: H6.1 이 Dream t0 에서 양수 -> 문맥 위치에서의 계산 근거.  tc 에서만 양수 -> 시점 차이를 먼저 설명해야 함.  H6.2 만 양수 -> 분산·중복 경로 가설.
  '차이가 없다' 는 CI 가 [-5, 5] %p 안일 때만 쓴다.

### 설계 (build_layout.py -> data/musique_layout.jsonl)
- 사실 문장 두 개를 고정하고 **연결 문장만 움직인다.**  문서 9칸 (0-8).  사실은 칸 2 와 칸 6 에 고정.  연결 문장 A 는 칸 k ∈ {1, 3, 4, 5, 7}.
- 정답 사실이 앞 칸인 경우와 뒤 칸인 경우는 원래 / 교환 (A<-X vs A<-Y) 으로 만든다.  즉 같은 물리적 배치에서 연결 문장의 이름만 바뀌면 정답과 다른 값의 역할이 뒤바뀐다.
- x = d(A, 정답 사실) - d(A, 다른 사실) (칸 단위).  k 가 1, 3, 4, 5, 7 일 때 다른 사실이 뒤 칸이면 x = -4, -2, 0, +2, +4, 다른 사실이 앞 칸이면 부호가 반대.  양수일수록 다른 사실이 연결 문장에 가깝다.
- 조건: U (연결 B 없음), L (연결 B 있음).  L 의 B 연결 문장은 칸 0 또는 8 (문항별 고정, 절반씩) 이라 k 와 겹치지 않는다.  나머지 칸은 무관한 실제 문서 (70-110 토큰으로 제한해 칸 거리 = 토큰 거리에 가깝게).
- S_e, S_l: 사실이 하나뿐인 확인용 (사실 칸 2 또는 6, 연결 칸 4).
- 40 문항 x 관계 틀 10 = 400 문항, seed 23.  X 와 Y, A 와 B, V1 과 V2 는 토큰 수가 같다.  사람 이름은 v3, v4 와 겹치지 않는다 (머리 개체·값은 이름 풀이가 작아 겹칠 수 있음).

### 분석 집합과 통계 (grade_layout.py)

- H10.1 (주, 용량-반응): 문항마다 다른 값 선택 y 를 x 에 회귀 (역할 고정효과; 설계가 균형이라 기울기 = Σxy / Σx²).  모델 x 조건마다 평균 기울기를 x = -4 -> +4 의 차이 (기울기 x 8, %p) 로 보고.  Qwen U, L 두 개에 Holm 보정.

- H10.2 (v8 확인): (a) 역할 효과 = mean(다른 사실이 뒤 칸) - mean(다른 사실이 앞 칸), x 가 균형이라 순수 최근성 + 인과 가시성 효과.  k = 4 (x = 0) 만 따로도 보고.
  (b) 엇갈림 = k=1 에서 (다른 사실 뒤 칸, 멂) - (다른 사실 앞 칸, 가까움).  v8 은 L -10.0, U -6.1.  Qwen L, U 에서 CI 가 0 아래면 v8 확인.  (c) 일치 = k=7 에서 (다른 사실 뒤 칸, 가까움) - (다른 사실 앞 칸, 멂).

### 데이터와 입력 (patch_question.py)
- data/musique_bindpatch.jsonl 360 쌍의 src 문맥 (A<-X, B<-Y, C<-Z, 사실 aX, aY, aZ).  QA = "A 에 대한 질문" (정답 aX), QB = 같은 틀의 "B 에 대한 질문" (정답 aY).  A, B 는 토큰 수가 같아 위치가 맞는다.

### 개입
- 방향 2개 (QB -> QA, QA -> QB).  범주: 반영 = 주는 입력의 정답, 유지 = 받는 입력의 정답, Z값, 기타.
