# 7. SAE 대 hidden state, layer와 적용 범위 (Dream-v0-Base-7B)

이 폴더는 세 가지 질문을 다룬다.
- 정답/오답 신호를 SAE로 볼지, hidden state 자체로 볼지
- 어느 layer가 신호를 가장 잘 담고, 어느 layer에서 밀어야 가장 잘 고쳐지는지
- 방향을 어느 토큰 범위에 더해야 하는지

## 공통 설정
- **대상**: 같은 사실을 묻는 질문 5개 중 1~4개만 맞히는 사실(1/5~4/5)이다. 정답/오답만 구분하고, 오답 유형은 합친다.
- **상태**: 디노이징 step 0(답 칸이 하나도 채워지기 전)에서 프롬프트 마지막 토큰(`...\nAnswer:`의 끝)의 hidden state다.
- **교차 적합**: 주어를 5묶음으로 나눈다(`analysis/6_steering`과 같은 묶음). 신호나 방향은 나머지 4묶음으로 만들고, 평가할 묶음에 적용한다.
- **방향 B_L**: layer L에서, 사실마다 `mean(정답 h) − mean(오답 h)`을 구해 평균 낸 뒤 길이를 1로 맞춘다.
- **steering**: 생성 32번 forward마다 `c × mean‖h_L‖ × B_L`을 더한다. 세기는 그 layer의 평균 크기에 대한 비율 c로 맞춘다.
- **대조군 D**: 오답 행을 무작위로 반씩 나눈 평균 차이에서 B 성분을 빼, B와 직교하게 만든 방향이다.
  - 그대로 쓰면 B와 cosine이 −0.74~0.69까지 나와서 B를 밀거나 거꾸로 미는 효과가 섞인다. 두 방향 모두 hidden의 큰 분산 축을 잡기 때문이다.
- **실행**: repo 루트에서 `python3 analysis/7_sae_vs_hidden/<script>.py`. GPU가 필요한 스크립트는 `CUDA_VISIBLE_DEVICES=<gpu>`를 붙인다. 하나에 약 20GB가 필요하다.

## 결론
1. **SAE는 이 위치를 잘 복원하지 못하고, 정답/오답 방향의 절반을 놓친다.** 구별과 steering 모두 hidden state를 직접 쓰는 게 낫다.
2. **중간 layer에서 정점이 나오지 않는다.** 구별 성능은 뒤쪽 layer로 갈수록 오르다가 19~21번부터 평평해진다. 정답/오답 구분의 상한은 어느 layer든 약 0.67이다.
3. **미는 효과는 layer 24가 가장 크다.** 모든 질문에 밀었을 때 순이득은 L24, c=0.5에서 +5.0%p(95% 구간 +1.0~+8.7)다. layer 16은 효과가 약하다.

## 1. SAE 진단 (`sae_diagnosis.py`, CPU, `log_sae_diagnosis.txt`)
SAE는 `sae/dream_pilot_200M/dream-7b_L20_shared-0.2-0.5-0.8_s5_200M`이다. layer 20, 16k latent이고, 일반 텍스트(SlimPajama)를 무작위로 가려 2억 토큰으로 학습했다.

hidden h를 SAE 복원값 r과 오차 e로 정확히 나눈다(h = r + e).

| 위치 | FVU step 0 (0이 완벽) | FVU step 8 | 켜지는 latent 수 |
|---|---|---|---|
| **프롬프트 끝** | **1.79** | 0.81 | 1,484 |
| 질문 끝 | 0.18 | 0.27 | 1,144 |
| 주어 끝 | 0.33 | 0.31 | 5,831 |

FVU 1.79는 복원 오차가 행들 사이의 차이보다 크다는 뜻이다. 입력 스케일 문제는 아니다. 학습 때의 정규화 계수(0.923)를 적용해도 결과가 같다.

| 방향 | r(복원값)이 설명하는 몫 | e(놓친 부분)에 남는 몫 |
|---|---|---|
| B (같은 사실 안 정답 − 오답) | 51% | **49%** |
| K (관계 안 5/5 − 0/5) | 63% | 37% |

| probe 입력 | 같은 사실 안 정답/오답 | 5/5 대 0/5 |
|---|---|---|
| h (hidden) | **0.663** | **0.974** |
| e (SAE가 놓친 부분만) | 0.655 | 0.973 |
| r (SAE 복원값) | 0.641 | 0.969 |
| SAE activation (1,484개) | 0.643 | 0.964 |

28개 layer 전체 값은 로그에 있다.

## 3. layer별 steering (`caa_layers.py`, `log_caa_layers.txt`)
프롬프트 끝 토큰 1개에 layer 16, 20, 24 중 한 곳만 더한다. 대상은 1/5~4/5에서 무작위로 고른 오답 300행과 정답 300행이다(비율마다 ±2.5%p 정도 오차).

| 조건 | 오답 → 정답 | 정답 유지 |
|---|---|---|
| 개입 없음 | 2.3% | 92.3% |
| L16, c=0.5 / 1 | 10.7 / 11.3% | 83.0 / 75.0% |
| L20, c=0.5 / 1 | 18.7 / 25.3% | 81.7 / 70.3% |
| **L24, c=0.5 / 1** | **26.3 / 36.7%** | 76.3 / 53.7% |
| D, c=1 (L16 / L20 / L24) | 7.7 / 9.3 / 7.0% | 53.0 / 40.3 / 45.3% |

오답 → 정답 비율을 k별로 보면(c=1) 이렇다.

| k | L16 | L20 | L24 |
|---|---|---|---|
| 1/5 | 10% | 17% | **35%** |
| 2/5 | 8% | 28% | **34%** |
| 3/5 | 14% | 37% | **40%** |
| 4/5 | 21% | 32% | **44%** |

## 4. 순이득 (`net_gain.py`, CPU, `log_net_gain.txt`)
표본을 1/5~4/5의 실제 구성(오답 52.4%, 정답 47.6%)으로 가중했다.

`순이득 = 0.524 × (오답 → 정답 비율 변화) + 0.476 × (정답 유지 비율 변화)`이고, 같은 행의 개입 없음 결과를 기준으로 계산한다. 95% 구간은 행을 다시 뽑는 bootstrap(2,000회)으로 구했다.

| 조건 | 모든 질문에 밀 때 순이득 | 95% 구간 | 틀린 질문에만 밀 때 이득 |
|---|---|---|---|
| L16, c=0.5 | −0.1%p | −3.0 ~ +2.8 | +4.4%p |
| L16, c=1 | −3.5%p | −6.7 ~ −0.2 | +4.7%p |
| L20, c=0.5 | +3.5%p | +0.3 ~ +6.8 | +8.6%p |
| L20, c=1 | +1.6%p | −1.8 ~ +5.1 | +12.1%p |
| **L24, c=0.5** | **+5.0%p** | +1.0 ~ +8.7 | +12.6%p |
| L24, c=1 | −0.4%p | −4.5 ~ +3.9 | **+18.0%p** |
| D, c=1 | −16 ~ −21%p | | +2.4 ~ +3.7%p |

- 세게(c=1) 밀면 맞던 질문을 많이 망쳐서, 모든 질문에 밀 때는 c=0.5가 낫다.
- 틀린 질문만 골라 밀 수 있으면 c=1이 낫다.
- 표본 추정은 실제보다 높을 수 있다. L20, c=0.5를 1/5~4/5 전체 5,950행에 돌린 결과(`analysis/6_steering/caa_all_rows.py`, 방향은 정답 − broken)는 **+1.6%p**였다.

## 5. 아직 돌리지 않은 것
| 스크립트 | 내용 |
|---|---|
| `caa_positions.py` | layer 24 고정, 더하는 토큰 범위 비교. 범위는 끝 1개 / 끝 4개 / 프롬프트 전체 / 답 칸 32개 / 전체, 세기는 c = 0.25, 0.5, 1, 범위마다 D 대조군. 약 75분 |
| `extract_layers_steps.py` | 저장된 실행과 같은 배치(같은 길이 64개)로 전체를 다시 생성하며, 28개 layer × step 0/4/8/16/31의 프롬프트 끝 상태를 저장한다. 마지막 캔버스가 저장된 것과 같은 행만 쓴다. 1~2시간 |
| `layer_step_probes.py` | 위 결과로 layer × step 구별 성능을 본다. 답 칸 확신도만 쓴 비교 기준을 같이 낸다(뒤쪽 step은 이미 쓴 답을 읽는 몫이 섞이기 때문) |

`extract_layers_steps.py`는 Dream의 토큰 선택 함수(`sample_tokens`)를 칸 단위로 나눠 실행해 메모리를 줄인다. 칸마다 독립이라 결과 토큰은 같다.
